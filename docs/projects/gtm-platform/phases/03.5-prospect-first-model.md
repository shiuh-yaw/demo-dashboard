## PR A - expand + backfill

1. Migration `gtm_prospect_first` (additive):
   - `CREATE TYPE "ProspectStatus" AS ENUM ('ACTIVE','ARCHIVED');`
   - `Team` (id cuid, name, slug unique, createdAt) + `TeamMembership` (userId FK, teamId FK, unique pair, createdAt) + RLS both.
   - `ProspectTheme` (prospectId unique FK + the palette columns copied from Prospect's current theme columns - enumerate them from schema; leave identity: name/domain/notes/logoUrl/logo/companyUrl/description ON Prospect) + RLS.
   - Prospect: ADD `teamId` (nullable during backfill, then SET NOT NULL after UPDATE - same migration is fine: rows exist and get backfilled first), `createdById` (nullable FK), `status` (default ACTIVE), partial unique index `(teamId, lower(domain)) WHERE domain IS NOT NULL` - check existing data for violations first and document any collisions (merge is Phase 07's affordance; if collisions exist, create the index as NOT VALID or defer it with a documented note rather than failing the deploy).
   - DemoConfig: ADD `createdById` (nullable FK); `ALTER COLUMN "prospectId" DROP NOT NULL`.
   - User: ADD `deactivatedAt TIMESTAMP(3)`.
   - Seed default team; backfill: every Prospect -> default team; copy theme columns -> ProspectTheme rows; resolve `createdById` from `User.dynamicUserId = ownerId` joins (Prospect + DemoConfig); backfill TeamMembership for every existing User row.
2. `scripts/backfill-users/`: Dynamic admin API (survey existing dashboard Dynamic credentials - magic-send may already hold a server token; else add `DYNAMIC_API_TOKEN` placeholder to env validation + .env.example) -> list environment users -> upsert User rows for `ALLOWED_EMAIL_DOMAINS` emails only (dynamicUserId = sub, role default MEMBER, membership in default team) -> re-run the createdById resolution UPDATEs.
